# Fight Health Insurance

Fight Health Insurance is a free tool that helps patients appeal health
insurance denials. A patient uploads their denial letter, and the site drafts
an appeal, explains the denial, and points to next steps and the regulators
for their state. This repository is the site at
[fighthealthinsurance.com](https://www.fighthealthinsurance.com/) and its API:
a Django 5.2 app, with React/TypeScript bundles for the chat and a few other
pages.

## Fight Paperwork

The same code also serves Fight Paperwork, the professional version at
fightpaperwork.com. If you're a provider, practice, or hospital system, we're
building tools to integrate into your workflow so your patients can fight
denials more effectively. Learn about the
[professional version](https://www.fighthealthinsurance.com/pro_version) or
explore [patient and market access partnerships](https://www.fighthealthinsurance.com/professionals/patient-access),
and reach us for more information from the
[partner section of the Join the Fight page](https://www.fighthealthinsurance.com/how-to-help#providers).

For development: new self-serve professional signups are off in production and
on under the `Dev` and test settings, so the signup flow works locally
(`NEW_PROFESSIONAL_SIGNUP_ENABLED` in `fighthealthinsurance/settings.py`).

## Privacy rules

The app handles people's health information (PHI). Keep to these rules in
anything you add.

- **No PHI in logs, Sentry or the browser console.** Production bundles strip
  `console.log`/`info`/`debug` (`fighthealthinsurance/static/js/webpack.config.js`),
  but `console.warn`/`error` still ship, so never put PHI in them. Production
  also turns off loguru's variable dumps in tracebacks
  (`fighthealthinsurance/settings.py`).
- **Identifying details are scrubbed in the browser before upload.**
  `fighthealthinsurance/static/js/scrub_scrub.ts` swaps names and IDs for
  placeholders such as `{{FIRST_NAME}}` and keeps the originals in the
  browser; `descrub()` in `fighthealthinsurance/static/js/appeal.ts` puts them
  back into the finished letter. The chat does the same
  ([docs/chat-pipeline.md](docs/chat-pipeline.md)).
- **Uploaded documents are encrypted at rest** with `EncryptedFileField` (the
  `*_enc` fields in `fighthealthinsurance/models.py`, keyed by `DEFF_SALT` and
  `DEFF_PASSWORD`).
- **No case credential in a URL.** Back links carry an encrypted reference
  ([docs/back-link-references.md](docs/back-link-references.md)); follow-up
  links carry a hashed email, not the address.
- **Personal fields stay out of error reports.** Flow views wrap email and
  other personal POST fields in `sensitive_post_parameters`
  (`fighthealthinsurance/urls.py`).
- **Appeal-flow pages are personal.** A cached page must never carry the
  visitor who warmed the cache (`tests/sync/test_cached_pages_carry_no_visitor.py`),
  and flow pages get no public markdown twin
  (`fighthealthinsurance/agent_docs.py`). Patients can delete their data at
  `/remove_data`.
- **External models only with consent.** Denial text goes to a hosted model
  or service only when the user leaves the external-models consent on
  (`Denial.use_external`, on by default). Appeal generation
  (`fighthealthinsurance/generate_appeal.py`) and denial triage
  (`fighthealthinsurance/ml/denial_triage.py`) both check it; so should
  anything new. See [docs/ml-backends.md](docs/ml-backends.md).
- **Temporal payloads carry IDs, not case text**, and are Fernet-encrypted when
  `TEMPORAL_PAYLOAD_KEY` is set (`fighthealthinsurance/temporal_codec.py`).

## Run it locally

You need Python 3.12 or 3.13, Node.js 20+ with npm, tesseract-ocr, texlive,
pandoc, mkcert and git. Per-platform install commands, the conda option and
troubleshooting are in [docs/local-development.md](docs/local-development.md).

```bash
# from the repository root
python3.12 -m venv .venv && source .venv/bin/activate   # or python3.13
pip install -r requirements.txt -r requirements-dev.txt
./scripts/run_local.sh                                  # same as: make run-local
```

Then open **https://localhost:8000**. What the script does to the machine:

- **First run** (no `cert.pem`): `scripts/install.sh` creates `.venv`, installs
  tesseract-ocr and mkcert with `apt-get` or `brew` (using `sudo` if needed),
  and makes a certificate for localhost.
- On Linux with passwordless `sudo`, it may raise the inotify watch limit and
  write `/etc/sysctl.d/99-fighthealthinsurance-watches.conf`.
- Every run: rebuilds the JavaScript with npm when its sources changed,
  downloads and verifies the GeoIP database (once), migrates the SQLite
  database (`db.sqlite3`), and loads fixtures and local test logins (listed in
  [`setup_local_db.py`](fighthealthinsurance/management/commands/setup_local_db.py)).
  `FAST=FAST ./scripts/run_local.sh` skips the build and the database setup.
- If `kubectl` can reach the team's cluster, it port-forwards the cluster's
  model backends. Otherwise that step is skipped.

The Dev settings write outgoing email to `sent_emails/` instead of sending it.
Generating an appeal needs a model backend ([ML backends](#ml-backends)). The
Ray background actors do not run locally.

## Run the tests

Run tests only through tox (see [AGENTS.md](AGENTS.md)). Each env collects its
whole directory; arguments after `--` go to pytest and are added to that, so
narrow a run with `-k`, which matches test, class and module names.

```bash
# from the repository root
pip install tox                          # CI uses: uv tool install tox --with tox-uv
tox -e py313-django52-async-unit         # one suite
tox -e py313-django52-selenium -- -k appeal_generation   # part of a suite
tox -e py313-django52-sync -- -k test_no_multiline_hash_comments_in_any_template   # one test by name
./scripts/good_to_go.sh --py 313         # pre-push: 8 envs in parallel, with a summary
```

| tox env | Tests | Settings class | Notes | CI job |
| --- | --- | --- | --- | --- |
| `py313-django52-sync` | `tests/sync/` | `TestSync` | Serial. Does not build the JS; see below. | `tests-sync` |
| `py313-django52-async` | `tests/async/` | `Test` | `-n auto` | `tests-async` |
| `py313-django52-async-unit` | `tests/async-unit/` | `Test` | `-n auto` | `tests-async-unit` |
| `py313-django52-sync-actor` | `tests/sync-actor/` | `TestActor` | Ray actor tests | `tests-sync-actor` |
| `py313-django52-selenium` | `tests/selenium/` | `TestSync` | Real browser; failed tests rerun twice | `tests-selenium` |
| `py313-django52-temporal` | `tests/temporal/` | `Test` | Downloads the Temporal test server on first run | not in CI |

- `py312-` and `py311-` variants exist too. CI runs only 3.13. Bare names
  (`tox -e async-unit`) use the Python tox runs on.
- Every test env except `sync` builds the JavaScript first
  (`scripts/test_setup.sh`). `tests/sync/test_form_persistence_behaviour.py`
  runs the built `dist/formPersistence.bundle.js` under node and fails when it
  is missing, so build before your first `sync` run and again after a
  TypeScript change: `./scripts/build_static.sh`, or `npm install` and
  `npm run build` in `fighthealthinsurance/static/js/`. CI builds it first with
  `./scripts/ci_npm_build.sh`.
- tox hands your whole shell environment to the tests (`passenv = *` in
  `tox.ini`), so a key you exported for the dev server reaches the test run
  too. Tests must not read it. A test that needs a credential sets one with
  `patch.dict(os.environ, ...)` for that test only; a new env-configured model
  backend adds its variables to `_AMBIENT_BACKEND_ENV_VARS` in
  `tests/async-unit/conftest.py`. The full rule is in [AGENTS.md](AGENTS.md).
- `good_to_go.sh` runs sync, async, async-unit, sync-actor, selenium, black,
  mypy and prettier. It does not run temporal.
- Plain `tox` runs every env for every installed Python (3.11 to 3.13) plus the
  linters, which is slow. Pick the env for what you changed.

## Guard tests that only let counts fall

Several tests in `tests/sync/` count something across the templates or CSS.
They fail when a count goes up, and also when usage drops without the recorded
number coming down with it. If one fails because a count rose, use the site's
own classes or values instead (the failure message says what); raise a number
only in the same commit, with a reason. If one fails because usage fell, lower
the recorded number.

| Test | Counts | Recorded numbers |
| --- | --- | --- |
| `test_bootstrap_ratchet.py` | Bootstrap classes, in total and per template. `INSTEAD` says what to use. | `BASELINE`, `PER_TEMPLATE` |
| `test_spacing_scale.py` | Spacing values off the 4px grid in `custom.css` and `main.css` | `BASELINE` |
| `test_contrast.py` | Color-contrast exceptions, which can only shrink | `EXCEPTIONS`, `UNRESOLVED`, `UNREACHED`, `TEMPLATE_BASELINE` |

Other guards worth knowing, also in `tests/sync/` unless a path is given:
`test_type_scale.py` (16px floor for running text and inputs),
`test_every_page_opens_the_same_way.py` (each page opens with an image hero or
`fighthealthinsurance/templates/partials/page_title.html`),
`test_page_columns.py`, `tests/selenium/test_selenium_page_widths.py`,
`test_migration_state.py` (missing or conflicting migrations), and
`test_template_comments.py` (a multi-line `{# #}` comment renders on the page,
so use `{% comment %}`).

## Where common changes go

### How a denial becomes an appeal letter

1. `/generate_appeal` (`GenerateAppeal` in `fighthealthinsurance/views.py`)
   renders `fighthealthinsurance/templates/appeals.html`, whose script opens
   the WebSocket `ws/streaming-appeals-backend/`.
2. `StreamingAppealsBackend` in `fighthealthinsurance/websockets.py` streams
   from `AppealsBackendHelper.generate_appeals` in
   `fighthealthinsurance/common_view_logic.py`.
3. That calls `AppealGenerator.make_appeals` in
   `fighthealthinsurance/generate_appeal.py`, which builds the prompts and
   calls the models: internal ones first, hosted ones as the backup only when
   `Denial.use_external` allows it.

The denial itself is created earlier in the flow by `DenialCreatorHelper`
(`fighthealthinsurance/common_view_logic.py`). The chat does not use this
path: its model returns a `create_or_update_appeal` call, and `AppealTool`
(`fighthealthinsurance/chat/tools/appeal_tool.py`) saves the appeal
([docs/chat-pipeline.md](docs/chat-pipeline.md)).

### A new public content page

- **View:** a subclass of `StaticIshView` in `fighthealthinsurance/views.py`
  that sets `template_name`. It caches the whole response and blanks the
  visitor's context first. `tests/sync/test_cached_pages_carry_no_visitor.py`
  fails if a page is cached any other way (a new `cache_page(` call).
- **Route:** a named `path()` in `fighthealthinsurance/urls.py`.
- **Template:** `fighthealthinsurance/templates/<name>.html`, extending
  `base.html` and filling `{% block title %}` and `{% block content %}`.
- **Column:** the first element in `{% block content %}` is
  `<div class="fhi-page">` (the reading column, 760px) or
  `<div class="fhi-page-wide">` (1140px, for grids and indexes). Add
  `fhi-page-centred` to centre the title. No Bootstrap `container`.
- **Title:** the first thing in the column is
  `{% include "partials/page_title.html" with title="..." %}` (add
  `lede="..."` for a one-line intro). It is the page's only `<h1>`. Entry pages
  with an image hero, such as Explain My Denial, open with the hero instead.
- **Tests:** add the URL name to `CONTENT_PAGES` in
  `tests/sync/test_every_page_opens_the_same_way.py`, and the template and its
  column class to `ON_A_COLUMN` in `tests/sync/test_page_columns.py`.
- **Listing:** add the URL name to `StaticViewSitemap.items()` in
  `fighthealthinsurance/sitemap.py`. That also gives the page a markdown twin
  (`fighthealthinsurance/agent_docs.py`); a `PAGE_NOTES` entry there describes
  it in the site's `/llms.txt`.

### A new microsite

- Add one entry to `fighthealthinsurance/static/microsites.json`, keyed by its
  slug, with a `slug` field equal to the key. No view, template or route is
  needed: `MicrositeView` serves `/microsite/<slug>/` and `/treatments/` lists
  it.
- The required keys are `REQUIRED_MICROSITE_KEYS` in
  `fighthealthinsurance/microsites.py`, each a non-empty string. The tests also
  want at least one `common_denial_reasons` and one `evidence_snippets` entry,
  and reject any key missing from `ALL_VALID_MICROSITE_KEYS` in
  `tests/async/test_microsites.py`.
- At runtime nothing is raised: an entry missing a required key is logged and
  skipped, and a JSON syntax error drops every microsite. Check the file with
  `tox -e py313-django52-async -- -k microsite` and `tox -e prettier`.
- The server reads the collected copy in `static/` and keeps it for the life of
  the process (`_find_microsites_json` in `fighthealthinsurance/microsites.py`).
  To see an edit locally, restart `./scripts/run_local.sh` without `FAST`.

## Configuration

- **Settings classes** (django-configurations, in
  `fighthealthinsurance/settings.py`): `Dev`, `Test`, `TestSync`, `TestActor`,
  `Prod`. `DJANGO_CONFIGURATION` picks one; when it is unset, `manage.py` uses
  `ENVIRONMENT`, else `Dev`. tox sets the test class for each env.
- **Environment variables must be exported.** Most settings, including every
  model backend and GeoIP, are read with `os.getenv`, and nothing loads `.env`
  into the process environment. `.env` is read only by `get_env_variable`
  (`fighthealthinsurance/env_utils.py`, via python-decouple). To use a `.env`
  file for everything, export it in the shell first: `set -a; . ./.env; set +a`.
- [`.env.example`](.env.example) and [API_KEYS_SETUP.md](API_KEYS_SETUP.md)
  list the variables. Both still describe OctoAI (`OCTOAI_TOKEN`), which no
  code reads, and `.env.example` still has old Azure defaults and a backend
  port that collides with the dev server. For model backends, follow
  [docs/ml-backends.md](docs/ml-backends.md).

### ML backends

The app needs at least one model backend to generate appeals: a hosted API
(`ANTHROPIC_API_KEY`, `DEEPINFRA_API`, or Azure) or a self-hosted
OpenAI-compatible server (`HEALTH_BACKEND_HOST`/`_PORT`/`_MODEL`). Appeals try
internal models first and use hosted ones as the backup tier. Setup, the Azure
details and `ENABLED_REMOTE_MODELS` are in
[docs/ml-backends.md](docs/ml-backends.md); the deploy-time health check is in
[docs/model-backend-health.md](docs/model-backend-health.md).

### GeoIP

The chat's US-state guess and ASN tracking need a geoip2fast city database,
enabled by `FHI_GEOIP_CITY_DB`. `scripts/run_local.sh` and `k8s/Dockerfile`
fetch and verify it with `scripts/fetch_geoip_db.sh`. Why the digest is pinned,
and how to update it: [docs/geoip.md](docs/geoip.md).

## Contributing

1. Create a branch from `main`.
2. Make small, focused commits.
3. Run the tox env for what you changed, or `./scripts/good_to_go.sh --py 313`
   before pushing. Add `tox -e py313-django52-temporal` when you touch Temporal
   code, since neither CI nor `good_to_go.sh` runs it.
4. Run `tox -e black` and `tox -e mypy`, and `./scripts/check_shell_style.sh`
   if you changed a shell script.
5. Screenshots for UI review can go in `docs/ux-evidence/`; pull request diffs
   collapse them.
6. Open a pull request. CI runs the jobs listed above.
