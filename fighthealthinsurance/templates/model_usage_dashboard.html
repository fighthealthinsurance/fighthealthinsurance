Which ML models get picked, and what state each one is in today. Sources: ProposedAppeal (denial flow), Chooser - Appeal, Chooser - Chat. ProposedAppeal is real patients choosing among the drafts written for their own case. A case counts once, for the pick recorded last, and pick rate = cases picked / cases where the model had a draft on the page. The chooser tables are anonymous votes on synthetic cases: win rate = votes won / votes the model was shown in. A rate with no denominator shows as a dash, never 0%. Windows are rolling (last 24 hours / 7 days / 30 days, anchored on the pick or vote time); All Time additionally includes rows predating timestamp tracking. Buckets that are not models: “synthesized” = drafts merged from several models; “legacy-unattributed” = historical picks recorded before model tracking whose generating model cannot be recovered; “legacy-unresolved (Class)” = legacy chooser rows that stored a Python object repr, aggregated by model class; “(template, non-AI)” = the non-AI template letter; “(shared-appeal text)” = text submitted through the share-appeal form, which may never have been a draft; “(unattributed)” = any other pick that could not be matched to a generated draft; “unknown” = a call record with no model name. These buckets have no offered or presented counts by design.

Each model row carries its state now, read from this deployment's model settings and the stored health checks; this page never calls a model. The counts beside it are history, so a retired model can still have picks. Tags link to the Model Backend Status page.

  • internal, healthy external, healthy on our own servers (internal) or a paid provider (external), and the latest health check passed.
  • internal, no health check yet external, no health check yet configured now, with no health check stored since.
  • context only used for context lookups, never to write letters.
  • failing: FAIL_TIMEOUT the latest health check, or the configuration, failed with that category.
  • not configured disabled its provider has no settings here, or ENABLED_REMOTE_MODELS leaves it out.
  • not in the code any more no backend in this deployment's code or model settings has this name.
  • placeholder bucket not a model: one of the buckets above.
  • state unavailable the model settings could not be read; the server log says why.
